## 2. 剩下的工作

- **代码签名**：SignPath Foundation 的开源签名申请（docs/10 §3）。
- **自动更新**：Tauri updater + 签名校验；在那之前「关于」页可以手动检查更新。
- **winget 清单**。
- **英文界面**：界面文字目前只有中文。
- **性能回归**：按第 3 节的指标在发版前跑一遍并记录。
- **用户文档**：快速上手、快捷键表、主题制作指南。

## 3. 决定不做的

| 不做 | 原因 |
| --- | --- |
| 窗口材质（Mica / 亚克力） | 浅色主题下透出的壁纸会拉低文字对比度；界面已经成熟，精力放在功能上 |
| 背景图轮播、按配置档换背景、从图片生成主题 | 同上，收益小 |
| 可视化主题编辑器 | 导入现成配色方案更省事；细调可以直接改设置文件，保存即生效 |
| win32 输入模式 | 普通 VT 输入下 PSReadLine、ssh、vim 都正常，mooncli 自己的组合键在 xterm.js 层截住（docs/02） |
| PSReadLine 预测插件 `MoonCli.Predictor` | 要额外发布 C# 模块和管道协议；补全面板已覆盖按目录、成败排序的历史（docs/04 §5） |
| 读登录凭证调未公开接口拿额度 | 合规红线（docs/07 §1） |

## 4. 性能指标

| 指标 | 目标 | 怎么测 |
| --- | --- | --- |
| 冷启动到提示符出现 | < 800ms（不含用户 profile 耗时） | 启动时打点 |
| 新建标签页到提示符 | < 300ms（不含 profile） | 同上 |
| 按键到屏幕显示 | 比 Windows Terminal 多不超过 5ms | Typometer 类工具对比测试 |
| 大量输出 | `Get-Content` 一个 100MB 文件，界面不卡死，可随时 Ctrl+C | 手动 + 脚本 |
| 滚动帧率 | 60fps（有背景图时也是） | Chrome DevTools 性能面板 |
| 内存 | 1 个标签页 < 150MB，每多一个标签 < 25MB（1 万行回滚） | 任务管理器 |
| 空闲 CPU | 窗口在后台时 < 0.5% | 同上 |

## 6. 风险和对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| xterm.js 在 WebView2 里的性能不如原生 | 大量输出时卡 | 批处理 + 背压；WebGL 渲染；M1 就做压测，不达标早调整 |
| 悄悄发组合键取补全，和用户快速输入抢顺序 | 输入错乱 | 只在提示符上且用户停顿时发；M4 专项测试；常驻面板默认不用这个来源 |
| Claude Code / Codex 的扩展点或数据格式变化 | 额度、上下文或提醒失效 | 所有解析都容错，缺字段就显示原因而不是报错；真机检查脚本（`crates/mooncli-agent/tests/real_machine.rs`）在版本更新时快速复核 |
| ConPTY 的已知问题 | 显示错乱 | 自带新版 conpty.dll；保留系统 ConPTY 开关方便对比排查 |
| 用户 profile 很慢 | 启动慢被算到 mooncli 头上 | 启动页显示"正在加载 PowerShell 配置文件…"及耗时，帮用户定位 |
