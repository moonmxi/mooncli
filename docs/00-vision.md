# 00 愿景与范围

## 一句话

mooncli 是一个 Windows 上的 pwsh 终端，浅色好看、记性好、手感顺，还能看懂每个标签页里在发生什么（包括 Claude Code、Codex 这类命令行 Agent）。

## 为谁做

- 主要用户：每天在 Windows 上用 pwsh 写代码、跑 Agent、连服务器的开发者。
- 第一位用户就是作者本人：偏好浅色、在意外观、同时开很多会话、重度使用 Claude Code / Codex。

## 四个重点

| 重点 | 想达到的效果 |
| --- | --- |
| 外观 | 浅色主题是一等公民，不是"深色主题反过来"。布局清楚，主题、字体、颜色、背景都能细调。 |
| 命令记忆 | 敲过的命令找得回来；输到一半能看到所有可选项；面板可以随叫随到，也可以常驻。 |
| 使用体验 | 滚动跟手、复制粘贴不出意外；ssh、vim 这类场景下按键原样传过去，不"自作聪明"。 |
| 智能程度 | 标签页自动显示目录、程序、Agent 标题和状态；Claude Code、Codex 的额度和当前会话的上下文实时可见，一轮跑完弹通知提醒。 |

## 不做什么（至少第一版不做）

- **不跨平台**：只做 Windows 10 1809+ / Windows 11。macOS、Linux 以后再说。
- **不替换 shell**：不自己写 shell，也不改造 pwsh 的语法。pwsh 原来能做的都照常能做。
- **不做"输入框模式"**：不像 Warp 那样把输入区换成自己的编辑器。输入仍然交给 pwsh/PSReadLine，mooncli 只在旁边"帮忙"。这是 ssh 后补全不失灵的根本保证（见 [05](05-interaction.md)）。
- **不内置 AI 对话**：不接大模型 API。"智能"指的是看懂会话状态，不是替你写命令。
- **不碰 Agent 的账号接口**：用量数据只用官方扩展点和本机文件，不读登录凭证、不调用未公开接口（见 [07](07-agent-monitor.md)）。
- **不做云同步**：配置和历史只在本机。用户可以自己把配置目录放进网盘或 git。

## 设计原则

1. **不抢键**。只有确认当前在"本机 pwsh 的提示符"上时，mooncli 才处理快捷键里的补全类按键；其它时候（ssh、vim、正在运行的程序）按键一律原样透传。
2. **默认就好看**。不改任何设置，打开就应该是一个舒服的浅色终端。
3. **能改，但不用改**。所有外观和行为都可配置，但默认值要经过推敲。
4. **快是功能**。输入延迟、滚动帧率、启动时间都有明确指标（见 [09](09-roadmap.md)），每个里程碑都要测。
5. **出问题能退回去**。shell 集成脚本坏了，终端也要能用，只是少了智能功能。
6. **数据留在本机**。历史、用量、配置都不上传。

## 参考了谁

| 终端 | 学它什么 |
| --- | --- |
| Windows Terminal | ConPTY 的用法、自带新版 ConPTY、配置结构、shell 集成标记 |
| WezTerm | 自带 conpty.dll / OpenConsole.exe 的做法、portable-pty、可编程配置 |
| VS Code 终端 | pwsh shell 集成脚本、命令装饰、从 pwsh 拿补全结果的方法 |
| Warp | 命令块、历史搜索面板的交互；也是"输入框模式导致 ssh 问题"的反面参考 |
| Tabby | xterm.js 的工程实践、插件化、ssh 管理 |
| Atuin | 带上下文的历史库（目录、退出码、耗时）和搜索界面 |
| Fig / inshellisense | 基于"命令说明书"（spec）的子命令和参数补全 |
